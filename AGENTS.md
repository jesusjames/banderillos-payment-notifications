This is an Expo/React Native app, **Android only**. It forwards Bancolombia transfer SMS to a Telegram group.

## Expo has changed — do not trust your training data

Expo ships breaking changes every SDK release. Before writing code that touches an Expo or React Native API,
read the `expo` major version in `package.json` and check the matching docs at
`https://docs.expo.dev/versions/v<major>.0.0/` (index with corrections: https://docs.expo.dev/llms.txt).

## Project rules

- Everything is local: no backend, no database, **no EAS**, no cloud services. The only external call is the
  Telegram Bot API.
- Expo Router with three routes in `src/app/`: `index` (home), `historial`, `configuracion`. Keep non-route code
  (components, hooks) outside `src/app/`. Use the native `Stack` only: `react-native-gesture-handler`,
  `react-native-reanimated` and `react-native-worklets` are excluded from Android autolinking in
  `react-native.config.js` (unused; their C++ breaks on Windows paths / JDK 25).
- Builds run on the user's **JDK 25** (shared with other projects; don't switch to JDK 17).
  `plugins/withJdk25Support.js` pins prefab 2.0.0 because prefab 2.1.0 loads JNA and AGP treats the JDK 24+
  "restricted method" warning as an error.
- Native code lives in the local Expo module `modules/sms-forwarder/` (Kotlin). `android/` is generated by
  `expo prebuild` (Continuous Native Generation): never edit it by hand; use `app.json`, `plugins/` or the module.
- SMS reception must keep working with the app closed: it is a manifest-declared `BroadcastReceiver`, never a
  JS listener.
- The bot token is never hardcoded or committed. Keystore and signing credentials are never committed.
- Forward the SMS text exactly as received; do not parse or trim it.

## Commands

```bash
npx expo install <package>  # ALWAYS use instead of npm add — resolves SDK-compatible versions
npx expo run:android        # local development build (Expo Go cannot load the native module)
npm run typecheck           # tsc --noEmit
npm run setup:keystore      # one-time: creates the signing keystore + credentials in ~/.gradle
npm run build:apk           # signed release APK in dist/ (JDK 17+, tested on 25; see README)
```

Run the typecheck before declaring any task done. Native changes need a rebuild (`npx expo run:android`).
